# Writing rules for project management issues

Back to [the design](README.md).

The [shared writing rules](../issue-refinement/B-definition-of-ready.md#writing-rules) give the issue requirements. Use the [rubric](../issue-refinement/C-writing-rubric.md) to review examples and drafts.

## Titles and lint

See the [shared title and process-verb rules](../issue-refinement/B-definition-of-ready.md#titles-and-process-verbs) and the [planned title, hedge, and reference lint](../issue-refinement/B-definition-of-ready.md#content-checks) for what the tools kernel flags after a later pm schema change. The [refinement procedure](../issue-refinement/A-refinement-procedure.md#vale-pass) gives the Vale pass.

## Research

Use the [Research definition and section limits](A-content-model.md#research) to draft an investigation whose deliverable is a written finding. The [Research done check](A-content-model.md#research) specifies what the reviewer looks for.

## Templates and the guide

- Use sample text that passes the checks for its variant.
- Print the writing rules and examples from schema hints with `tbhbdev pm guide <type>`.
- Use the rule and its passing example as the hint for a refusal.

## Imports

Apply the same writing rules to staged files in the [tracker import](E-import.md#staging-and-refinement). A check that would refuse issue creation also refuses a staged file.
